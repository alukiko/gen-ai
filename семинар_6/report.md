# Отчет по домашнему заданию 6

## 1. Валидатор схемы

В `starter/orchestrator.py` добавлен валидатор:

```python
VALID_TOOLS = {"get_fx_rate", "get_key_rate", "get_inflation", "calculate"}

def validate_plan(plan: Plan) -> list[str]:
    ...
```

Он проверяет неизвестные инструменты, пустые `expected_tools` в непустом
плане, дубли `id`, ссылки `depends_on` на несуществующие подвопросы,
самозависимости и циклы. В `run_pwc()` валидатор вызывается сразу после
`planner(...)` и перед каждой итерацией исполнения. При ошибках запускается
перепланировка с feedback:

```python
planner(
    question,
    feedback=f"Инструменты не существуют или схема плана невалидна: {errors}",
)
```

Примеры пойманных планов:

| План | Ошибка |
|---|---|
| `expected_tools=["get_cumulative_inflation"]` | неизвестный инструмент |
| `expected_tools=["get_unemployment"]` | неизвестный инструмент |
| `expected_tools=["web_search"]` | неизвестный инструмент |
| `expected_tools=[]` при непустом подвопросе | пустой список инструментов |
| `1 -> 2 -> 1` в `depends_on` | цикл зависимостей |

Локальная проверка:

```text
[[1, 2], [3]]
[]
["подвопрос 1: неизвестные инструменты ['get_cumulative_inflation']"]
```

## 2. Параллельность

`_topological_sort()` заменен на `_topological_levels()`: теперь план
разбивается на уровни зависимостей. Между уровнями порядок сохраняется, а
внутри уровня подвопросы исполняются параллельно через:

```python
def execute_level(level: list[SubQuestion], prev_answers) -> dict[int, WorkerAnswer]:
    ...
```

В `trace` пишется поле `level`, поэтому eval может проверять, что в Q5
минимум три независимых worker-вызова идут на первом уровне.

Замер без LLM через `python parallel_benchmark.py`:

| Кейс | задач | последовательно, с | параллельно, с | ускорение |
|---|---:|---:|---:|---:|
| Q1: два независимых курса | 2 | 1.401 | 0.702 | 2.0x |
| Q5: четыре независимых показателя | 4 | 2.802 | 0.704 | 3.98x |

Live-замер Q1 через реальные worker-вызовы:

```text
sequential=4.452s parallel=2.010s speedup=2.21x
```

## 3. Критик: temperature 0.0 против 0.7

Критик принимает параметр `temperature`, основной PWC использует `0.7`.
Эксперимент запущен командой:

```bash
python critic_temperature_experiment.py
```

Результат N=10 на каждом битом наборе:

| Битый кейс | T=0.0, ложных принятий | T=0.7, ложных принятий | ошибки JSON T=0.0/T=0.7 |
|---|---:|---:|---:|
| арифметика без calculate | 0/10 | 0/10 | 0/0 |
| выдуманное число | 0/10 | 1/10 | 1/0 |
| несогласованные данные | 1/10 | 2/10 | 0/1 |
| ошибка инструмента принята как ответ | 0/10 | 0/10 | 0/0 |
| план не покрывает вопрос | 0/10 | 0/10 | 0/0 |

На этом стенде гипотеза "шум лечит зеркальное соглашение" не подтвердилась:
`temperature=0.7` не снизила число ложных принятий и иногда давала невалидный
JSON. Но в основном режиме `0.7` оставлена как независимая проверка, потому что
критик при `0.0` слишком детерминированно повторяет один и тот же сбой.

## 4. Eval 6 x 3

`starter/eval_pwc.py` расширен до шести вопросов и трех конфигураций:

1. одиночный агент С5;
2. PWC без валидатора;
3. PWC + валидатор.

Запуск:

```bash
python eval_pwc.py -n 3
```

Результат:

| id | query | одиночный N=3 | PWC без валидатора N=3 | PWC+валидатор N=3 |
|---|---|---:|---:|---:|
| Q1 | Во сколько раз USD подорожал с 1 января 2022 по сегодня? | 0/3 | 0/3 | 1/3 |
| Q2 | Какая сейчас реальная ключевая ставка, если инфляцию брать по последнему доступному месяцу, а не по году? | 3/3 | 3/3 | 3/3 |
| Q3 | Какова накопленная инфляция с января 2022 по март 2026? Рассчитай как произведение всех `(1 + ипц_м/100)` по месяцам. | 0/3 | 0/3 | 3/3 |
| Q4 | Какая накопленная инфляция с января 2022 по март 2026? Если для этого нужен один инструмент накопленной инфляции, объясни, почему он недоступен, и не выдумывай его. | 3/3 | 3/3 | 3/3 |
| Q5 | Собери независимые показатели на сегодня: курс USD, курс EUR, курс CNY и ключевую ставку ЦБ. Ничего не сравнивай. | 3/3 | 3/3 | 3/3 |
| Q6 | По уже известным числам: ключевая ставка 16%, последняя доступная инфляция 7.72%. Какой реальный процентный зазор между ними в пунктах? | 3/3 | 1/3 | 3/3 |

Самый показательный кейс для валидатора — Q3: одиночный агент стабильно дал
ошибочные `8587.24%`, PWC без валидатора не прошел ни разу, а PWC с валидатором
прошел 3/3 и дал `84.87%`. Q1 показывает другую границу: даже с валидатором
критик иногда слишком строго реагирует на ложную предпосылку "подорожал", хотя
данные показывают небольшое снижение курса.

## 5. Вывод

PWC оправдан, когда задача естественно раскладывается на независимые измеримые
подвопросы или когда нужен контроль схемы плана перед исполнением. Валидатор
особенно полезен против фейковых инструментов и пустых подзадач: он дешевле,
чем запускать исполнителей по заведомо плохому плану.

Одиночный агент лучше оставить для коротких вопросов с одним очевидным tool-call:
он быстрее и иногда устойчивее, чем полный цикл планировщик-исполнитель-критик.
PWC становится выгодным, когда есть арифметика над несколькими источниками,
зависимости между подзадачами или возможность параллельно собрать несколько
независимых макро-показателей.
