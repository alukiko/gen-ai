# Итоговый проект: Tweet Engagement Agent

## 1. Задача и данные

Проект решает прикладную задачу SMM: до публикации оценить вовлеченность твита и предложить более сильную версию текста, дня и часа публикации. База взята из моего старого проекта `Tweets/`: датасет `Twitterdatainsheets.csv`, сохраненный `weekday_ohe.pkl` и `random_forest_model.pkl`. Текстовые признаки строятся через `bert-base-uncased`, как в исходном ноутбуке.

Целевая метрика вовлеченности нормируется в диапазон 0-10 по лайкам, ретвитам и охвату. Это не абсолютная бизнес-истина, а proxy-оценка, достаточная для сравнения вариантов одного поста.

## 2. Система

Путь данных:

1. Пользователь передает текст, день недели и час.
2. `rag.py` ищет похожие исторические твиты в корпусе.
3. `agent.py` просит LLM или fallback-генератор сделать варианты.
4. Каждый вариант оценивается инструментом `predict_engagement`: BERT-эмбеддинг + RandomForest.
5. Агент выбирает лучший вариант, проверяет ghost-числа/цитаты и запускает judge.
6. Результат сохраняется как JSON/CSV trace.

Техники курса: RAG, агент с инструментом, structured output с Pydantic и `field_validator`, LLM-as-judge, проверка галлюцинаций.

## 3. Оценка

Eval находится в `input/eval_cases.json` и содержит 15 входов. Скрипт `eval.py` измеряет:

- correctness/pass: judge пропускает результат и лучший score не хуже исходного;
- path: число шагов инструмента и список использованных инструментов;
- hallucination diagnostics: ghost-числа и ghost-цитаты;
- delta: изменение прогнозной вовлеченности.

Результаты после запуска сохраняются в `output/eval_results.json` и `output/eval_table.csv`.

Последний локальный прогон `python eval.py --no-llm`:

| Метрика | Значение |
|---|---:|
| Кейсов | 15 |
| Pass-rate | 1.0 |
| Средний прирост score | 0.141 |
| Ghost-числа | 0 |
| Ghost-цитаты | 0 |

Дополнительно проверен одиночный запуск `python run.py ...` в обычном LLM-режиме: ключи берутся из `../семинар_2/домашнее/.env`, LLM генерирует варианты, а LLM-as-judge возвращает структурированную оценку.

## 4. Где система ошибается

1. Если BERT/RandomForest обучались на смещенном Twitter-корпусе, агент может переоценивать хештеги и CTA, потому что это коррелировало с прошлыми данными.
2. Для сервисных сообщений вроде maintenance window модель иногда пытается усилить маркетинговость, хотя продакшен-цель такого поста - ясность, а не максимальная вовлеченность.
3. RAG по TF-IDF на коротких текстах плохо ловит смысловые парафразы и может доставать похожие только по хештегам.

## 5. Выводы

Система годится как черновой помощник для SMM: она быстро сравнивает несколько вариантов и оставляет проверяемый trace. В production я бы добавил ручные политики бренда, отдельную модель для типа поста и онлайн-калибровку на свежих метриках аккаунта.
